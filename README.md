# MENTA — The Athlete Operating System

MENTA is an AI-powered Athlete Operating System — one platform connecting training,
performance, film, recovery, academics, recruiting, teams, and athlete development.

**Brand mantra:** ONE ATHLETE. ONE PROFILE. ONE AI. ONE DEVELOPMENT PLAN.
**Tagline:** Build the Athlete. Build the Mind.

This repo is the Phase 1 foundation described in `MENTA-MASTER-BUILD-PLAN.md`
(not committed here — hand that file to future work on this repo, it's the
source of truth for build order, permissions, and legal/safety rules).

## Stack

- **Next.js 16** (App Router, Turbopack) + **React 19** + **TypeScript**
- **Tailwind CSS v4**, design tokens matching the MENTA marketing site (matte
  black, Space Grotesk / Inter / IBM Plex Mono)
- **Prisma** + **SQLite** in dev (swap to Postgres for production — one
  `DATABASE_URL` change, see below)
- Hand-rolled session auth (bcrypt + server-validated, revocable, DB-backed
  sessions) — no third-party auth SaaS
- **Anthropic API** for MENTA AI (server-side only, off by default until
  `ANTHROPIC_API_KEY` is set)

## Getting started

```bash
npm install
cp .env.example .env   # then edit SESSION_SECRET at minimum
npx prisma migrate dev # creates prisma/dev.db and applies migrations
npm run dev
```

Visit `http://localhost:3000`.

## Environment variables

See `.env.example` for the full list with descriptions. Summary:

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | Yes | SQLite file in dev; Postgres connection string in production |
| `SESSION_SECRET` | Yes | Signs session + password-reset tokens. Generate with `openssl rand -base64 32` |
| `APP_URL` | Yes | Used to build links in emails |
| `ANTHROPIC_API_KEY` | No | Turns on MENTA AI. Without it, the AI chat clearly shows "not connected" instead of faking a response |
| `RESEND_API_KEY` / `EMAIL_FROM` | No | Sends real password-reset emails. Without it, reset links are logged to the server console instead |

Never commit `.env`. It's already gitignored.

## What's actually working

- Account creation, login, logout, password reset, session management
  (view/revoke active sessions), change password
- Role field on every user (`SUPER_ADMIN`, `DEVELOPER`, `MENTA_STAFF`,
  `ORG_ADMIN`, `SCHOOL_ADMIN`, `ATHLETIC_DIRECTOR`, `COACH`, `TRAINER`,
  `ATHLETE`, `PARENT`) — enforced server-side in `src/lib/permissions.ts`,
  never just hidden in the UI
- Multi-step onboarding writing to a real `AthleteProfile` (soft — not
  enforced; a user can reach the rest of the app without completing it)
- Athlete profile with a real visibility model (private/team/organization/
  recruiting/public), with an enforced cap for minors (see below)
- Teams: create, join by invite code, roster, scoped server-side (a coach's
  access is scoped to their teams, never the whole org)
- Messaging: team group chat + 1:1 DMs between teammates, with block and
  report tooling
- Calendar: personal and team events
- Notifications: real, DB-backed, generated by real events (new message, new
  team event, onboarding complete, guardian-link requests)
- Goals: CRUD with action plan, progress, and target date
- Training: workout library (personal or team-scoped) with completion
  logging
- Performance: freeform stat entries with per-stat trends, works for any
  sport without a schema change
- Film: upload, permission-scoped library, HTML5 player with clip marking,
  highlight-reel builder. Video is served through a Range-aware streaming
  route with the same permission check as the metadata endpoint. Local-disk
  storage only right now — see "Requires infrastructure before production"
- Guardian linking: a `PARENT` account can request a link to an athlete by
  email; the athlete approves/denies/revokes from Settings
- Minors (`dateOfBirth` under 18): profile visibility cannot be set to
  `PUBLIC` — capped server-side to `RECRUITING`
- MENTA AI: real architecture (`/api/ai` → `src/lib/ai.ts` → Anthropic API),
  context built only from the requesting user's own data (profile, goals,
  calendar, training, performance, highlights). **Shows an explicit "not
  connected" state and does not fabricate a reply** when
  `ANTHROPIC_API_KEY` is unset.
- Audit logging for auth events, role-sensitive actions, and admin-relevant
  changes (`src/lib/audit.ts`, `AuditLog` table)
- Rate limiting on auth, AI, and messaging endpoints (in-memory — see note
  below)

## What's explicitly not live yet (and why)

Recovery, Mindset, Academics, Recruiting, and Safety all have real routes
(behind auth, in the nav) but render a `ComingSoon` panel that states the
phase and exactly what infrastructure each one needs before it can be real —
no fake data, no button that looks functional but isn't. See
`src/components/ComingSoon.tsx` and the pages under `src/app/(app)/`.

There is also no dedicated coach- or parent-specific dashboard yet (coaches
see team rosters; parents see linked-athlete access via guardian linking,
but not a distinct summary view), and no team-wide analytics view.

## Security notes

- Passwords hashed with bcrypt (cost 12)
- Sessions are opaque server-side tokens (HMAC'd, DB-backed, revocable) in
  `httpOnly`, `secure` (production), `sameSite=lax` cookies — not a bare JWT
  a client could forge
- All authorization checks live in `src/lib/permissions.ts` and are enforced
  in API routes / server components, not just hidden in the UI
- `proxy.ts` (Next 16's renamed `middleware.ts`) only does an optimistic
  cookie-presence redirect, per Next.js's own guidance against slow
  Proxy-layer data fetching — the real check is the DB-backed session lookup
  in every page/route via `requireUser()` / `getSessionUser()`
- Password-reset tokens are single-use, hashed at rest, expire in 1 hour, and
  invalidate all existing sessions on use
- The forgot-password endpoint responds identically whether or not the email
  exists, to avoid account enumeration
- **Rate limiting is in-memory** (`src/lib/rate-limit.ts`) — fine for a
  single instance, but resets on redeploy and doesn't coordinate across
  instances. Swap for a shared store (Redis/Upstash) before running more
  than one instance in production.
- Verified manually: an unauthenticated request to a protected route
  redirects to login; a second user cannot read a conversation they aren't a
  participant in (`404`, not a permission error that would confirm it
  exists); unauthenticated API calls return `401`.
- Not yet done: MFA, CSRF tokens (same-site cookies + POST-only mutations
  mitigate but don't fully replace this), dependency/security audit, load
  testing, third-party penetration test.

## Requires legal review before real users

Per `MENTA-MASTER-BUILD-PLAN.md` §4 — none of the following should be treated
as done by an AI writing code:

- Terms of Service, Privacy Policy (not yet drafted in-app)
- Any compliance claim (HIPAA, FERPA, COPPA, NCAA) — none are made anywhere
  in this codebase, and none should be added without an attorney
- Parent/guardian consent flow for minors — the data model exists
  (`GuardianLink`, `dateOfBirth` on `User`) but enforcement of an actual
  consent gate at signup is not yet built
- Recruiting and NIL features, once built (Phase 2+)

## Database

Dev uses local SQLite (`prisma/dev.db`, gitignored) for zero-config setup.
For production, point `DATABASE_URL` at Postgres — the schema
(`prisma/schema.prisma`) intentionally avoids native enum types so it works
unmodified against either connector. Run `npx prisma migrate deploy` in
production instead of `migrate dev`.

## Project structure

```
prisma/schema.prisma        Data model
src/lib/                    Server-only: prisma client, session/auth,
                             permissions, audit log, email, AI, validation,
                             rate limiting
src/lib/auth-guards.ts      requireUser() — server-component route guard
proxy.ts                    Optimistic route-protection redirect (Next 16)
src/app/(app)/               Authenticated app shell + all athlete-facing
                             routes from the Phase 1-2 page map
src/app/api/                Route handlers - the actual authorization
                             boundary for every mutation
src/components/             Shared UI
```
